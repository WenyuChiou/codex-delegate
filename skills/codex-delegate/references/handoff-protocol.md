# Fable↔Codex handoff protocol — files, not clipboard

## The problem this kills

Iterative collaboration (ai-review experiments, pre-registered probes,
multi-round implementation) between a Claude/Fable session and a Codex
session was running on manual copy-paste: paste Fable's output into the
Codex app, paste Codex's reply back. That loses provenance, truncates
context, invites transcription drift, and leaves no artifact trail.

The transport already exists — the brief/result file contract. This
reference just extends it to BIDIRECTIONAL, multi-round work.

## The protocol

All handoffs are files in the WORK repo under `.ai/handoff/`:

```
.ai/handoff/
  003_sanitize_floor.to_codex.md    # Fable -> Codex
  003_sanitize_floor.to_fable.md    # Codex -> Fable (same NNN + slug)
```

- This is a DELIBERATELY separate namespace from the two existing
  conventions — `.ai/codex_task_<name>.md` (single-shot brief,
  `task-template.md`) and `.ai/<agent>_task_<NNN>_<slug>.md`
  (splitter round, `multi-agent.md`): those are one-way task→result
  shapes; `handoff/` is a bidirectional round-trip. Do not mix them.
- `NNN` is monotonic per repo; one round-trip shares one `NNN_<slug>`.
- Every file is SELF-CONTAINED: context as repo-relative POINTERS
  (paths + line ranges + commit shas), never pasted content dumps.
  Large artifacts stay in repo files; the handoff carries their paths.
- Replies: <=250-word summary + artifact paths + explicit
  `STATUS: done | blocked(<why>) | question(<what>)`.
- `.ai/` stays gitignored per repo convention — these are transport
  artifacts, not deliverables; deliverables land as normal tracked files.

### When Claude drives (zero manual steps)

`Skill("codex-delegate", args="brief=.ai/handoff/NNN_<slug>.to_codex.md")`
— the wrapper runs codex headless and the reply lands on disk. No human
in the transport loop at all.

### When the human drives the Codex app (one fixed sentence, no pasting)

Precondition: the Codex app's workspace root must be the work repo that
contains `.ai/handoff/` — the sentence uses a repo-relative path. Then
type EXACTLY one sentence into Codex:

> Read .ai/handoff/003_sanitize_floor.to_codex.md and execute all
> instructions inside; write your reply to
> .ai/handoff/003_sanitize_floor.to_fable.md.

And one into Fable/Claude:

> Read .ai/handoff/003_sanitize_floor.to_fable.md and continue.

This exact pattern is field-tested once (n=1): the 2026-07-20
sanitize-hardening round on persona_framework ran as "Read
.ai/codex_task_sanitize_hardening.md and execute all instructions
inside" and shipped as a four-green PR.

Why reading a gitignored `.ai/` path works at all: Codex's own file-read
tool does NOT honor `.gitignore` (unlike the retired Gemini lane that
produced the F1 lesson in DELEGATION.md) — the same reason the existing
`.ai/codex_task_*.md` single-shot pattern already works, in both the
headless wrapper (which passes "Read <path>..." as the prompt, not the
content) and the interactive app. A future gitignore-honoring delegate
CLI wired into this pattern would need the stdin-piping accommodation
instead.

## Harness-aware handoffs

If the target repo carries the fable-method-harness conditional pointer
in its `AGENTS.md` (generated by `python scripts/setup_harness.py
--print-wiring` in that harness), do NOT re-teach harness discipline in
the handoff — the pointer's conditional block already decides activation
(measured: Codex 4/4 trigger recall, 0/2 routine over-trigger, 1/1
rollback; see the harness's `docs/runtime_activation_telemetry_2026_07_15.md`).
A handoff that restates the discipline pays the context twice.

## Exact usage telemetry (cost accounting)

Headless rounds should run `codex exec --json`: canonical usage =
`input + cache_read + cache_write + output` (reasoning tokens reported
separately, not folded in). This replaces log-size estimation and
produced 7/7 exact usage rows in the harness's v3 activation probe.
Record per-round usage in the `.to_fable.md` reply when cost matters.

## Anti-patterns

- Pasting file contents between the two UIs (the whole point).
- A handoff file that depends on chat history to be understood.
- Codex committing/pushing from a handoff round — the orchestrator
  reviews the diff and owns the commit ("delegate returned" is a
  mandatory review trigger).
- Running interactive multi-round design iteration in a NON-git
  workspace: the 2026-07-16..20 cover-art rounds ran in a zero-commit
  folder, so the iterations survive only in session logs. Put the
  workspace under git before round 1.
